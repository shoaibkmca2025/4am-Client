# CLAUDE.md

Guidance for AI coding agents working in this repository.

## What this is

A static website: hand-written HTML, CSS and plain JavaScript in `public/`. No framework, no npm, no build step, no backend. The owner explicitly wants it kept that way (fast load, no backend or admin panel). The previous React/Vite app and its API (portal, admin, blog, careers, certificates) were removed in October 2026; they are recoverable from git history before that change.

## Run and deploy

- Preview: `npx serve public` (clean URLs: `/services/seo` → `services/seo.html`).
- Deploy: Vercel serves `public/` directly. `vercel.json` sets `framework: null`, empty install and build commands, `outputDirectory: "public"`, `cleanUrls`, and redirects the removed backend routes (`/portal`, `/admin`, `/blog`, `/careers`, `/verify`) to `/`.

## Structure

- `public/index.html` — home page. Opens with `.vhero`: a full-screen looping night video (`public/assets/hero/`: `night-1080.mp4` landscape, `night-portrait.mp4` for portrait phones) over a `<picture>` still, Instrument Serif headline, Inter copy, liquid-glass button, and a pause button (WCAG 2.2.2). The video has book stacks the owner doesn't want shown (this is a software company): `.vprops` (aria-hidden) lays floating glass windows over them — a code editor, a deploy terminal, a phone app, a growth card. `.vprops` is sized like the video's object-fit: cover box (1920×1074, centred; `cqw` units inside), so the windows stay on the stacks at any landscape aspect; positions are fractions of that box, so re-measure them if the video is ever swapped. Hidden on portrait (the portrait crop shows no stacks). No backdrop blur on them: it would re-blur every video frame. **Day / night theme**: `html[data-theme]` is set by an inline `<head>` script on every page before first paint — the visitor's saved choice (`localStorage.theme`), else day from 06:00 to 18:00 local time, night otherwise; it also sets `html.at-hero` (dark glass header) only for night, the `theme-color` meta, and on the home page preloads the matching hero still. The header's `.theme-btn` (sun/moon, 44×44, beside "Start a project" / Menu) switches and saves it, with a View Transitions crossfade; `main.js` fires a `themechange` event that swaps the hero video and re-decodes the launch photo. Paired media are `.th-night` / `.th-day` elements (only the visible one downloads: all are `loading="lazy"`): hero stills and film — day is the free Scrollhaus OpenHero "Lumina AI" sunrise clip (MIT), ping-pong looped, `day-1600.mp4` / `day-portrait.mp4`, `day-poster(-tall).webp` — and the launch photo (`day-launch*.webp`, the same photo gradient-mapped to a midday sky). Day text over the hero and the scene sits on dark scrims (`.vhero::after`, `.scene__glow`) measured to ≥4.5:1 on the worst 10% of pixels; the code windows `.vprops` are night only (the day video has no book stacks). Below the hero, `section.scene#launch` (after the free Scrollhaus "Zenith" direction): a pinned stage holding one tall photograph (Zenith's violet moon-and-rocket photo, upscaled 2× with Lanczos, local contrast + sharpening, hue-shifted to the hero's night navy): `public/assets/launch/night-launch.webp` 1600w, `-2400.webp`, `-3072.webp` via `srcset`, and `night-launch-tall.webp`, the x .22–.78 slice that portrait screens actually show, via `<picture>`. Scroll drives one camera pan + push-in from the launch to the moon; the launch copy rises, blurs and fades, then "Marketing you can measure." and a glass results window (`.dash`, real client numbers from the Work section; an `.sr` sentence carries them for screen readers) arrive. Then `.solid` bone sections: services and work are `.loop` rows (one line of compact cards drifting right-to-left on their own; they ease to a stop on hover, focus, the Pause button or off screen; people move them with trackpad/Shift+wheel, the ‹ › buttons, arrow keys, or drag/swipe; reduced motion gets a native scroll row), plus marketplaces, numbers, all 100 projects, process, team, contact.
- `public/services/<slug>.html` — seven service pages, each with its own `<title>`, meta description, canonical, Open Graph tags and JSON-LD (`Service`, `BreadcrumbList`, `FAQPage`). Keep these in sync with the home page service list, the footer on every page, and `sitemap.xml`.
- `public/css/site.css` — every style. Two palettes with the same token roles: night (below, the default values) and day (`:root[data-theme="day"]` in the "day theme" block near the end: page #F4F8FC, text #0B2338, accent #1D5FA8). Any new colour must use the tokens or be given a day override; hard-coded light-on-dark colours break day mode. Service and project cards are glass panes (frosted fill, light edge, shadow) over soft colour glows painted on their row (`.loop`, `.sp-work`, `.others`); the moving rows skip the live `backdrop-filter` (it re-blurred every card every frame — most of the phone scroll jank) and paint the glow pre-saturated instead, so they look the same. Night palette, matched to the hero video and the launch scene (owner's request, replacing the earlier bone/sage/forest light theme). The token names are historical, the roles are what matter: `--bone` #061826 = page background, `--bone-2` #0C2233 = raised surfaces (cards, form), `--forest` #E8F0F8 = text (16.4:1), `--sage` #9FD0FF = accent / primary buttons (the moon's glow, 9.9:1; navy text on it), `--sage-soft` #12304A = chips, `--night-deep` #030F19 = footer, `--glass` = featured blocks (quote, CTA band, featured service card). So `color: var(--bone)` means navy text — only use it on light fills (`--sage`, light chips). The "night surfaces" block at the end of the old palette section overrides the blocks that used to be dark forest. Sketch inks (`--tomato`, `--gold`, `--sky`) are decoration only. Every text element passes WCAG AA on every page (checked with deferred sections forced to render, since Lighthouse skips them).
- `public/js/main.js` — ES module. Every page: menu, reveal-on-scroll (`.rv` → `.on`; inline SVG sketches with `pathLength="1"` draw in), counters (`data-count`), card tilt, copy buttons, contact form. Home only: the hero (video source picked by aspect ratio and set only after first paint, paused off screen, fades in on `playing`; header `at-hero` state), the loop rows, and the launch scene — progress p from the section bounds; the timeline eases toward it (settle 9/s) capped at 0.4/s so a flick plays out; it writes `--cam-*`, `--hero-*`, `--glow-o`, `--plat-*` on the section and stops its rAF loop when settled; the headline lines are uncovered when the scene arrives. Nav highlight: the section in view, nothing over the hero and scene.

## Rules that matter

- Below-the-fold containers (`.solid > .sec`, `.marquee`, `.foot`, `.sp-sec`) use `content-visibility: auto`: the first paint skips them and their fonts and lazy images wait. 5 s after load, `main.js` lays them out in idle slices so scrolling into them later doesn't pay for a first layout mid-scroll (that was the worst jank). Never read geometry inside one while it is still skipped (check the container's own box first, as the reveal code does, and keep its container list in sync): it forces a layout and pulls in its fonts. Fonts used only below the fold are warmed with `document.fonts.load` after first paint. Chrome's autofill lays out the contact form at start-up anyway; that is expected.
- No layout reads during start-up script: use `matchMedia` for viewport checks, not `innerWidth` (one such read cost 85 ms on a mid-range phone). The scene measures itself in its first animation frame.
- Launch scene: one photo, never a crossfade; filters only while the copy is mid-exit (`.is-blurring`), never at rest; `will-change` only under `.is-moving`. The dashboard is decorative (`aria-hidden`): from 641 px up it scales as one unit (`--s`); on phones (≤ 640 px) it reflows into a readable card stack (big figures, nav/tabs/log hidden). Its figures are real client results — keep them in sync with the Work cards, and don't invent numbers. Keep the camera maths in sync for the portrait slice (`--cam-q` → its own x). The photo is pre-decoded on load; no backdrop blur behind the window (it cost a re-render every scroll frame).
- Card rows: only a horizontal-dominant wheel (or Shift+wheel) is captured; vertical wheel always scrolls the page. After any manual move the row holds for 5 s before drifting again.
- The hero headline is the LCP element: it only rises, it never fades from opacity 0 (Chrome doesn't count text that starts invisible). The still is a `<picture>` (portrait source at `max-aspect-ratio: 4/5`); never give the `<video>` a `poster` or change it from JS — swapping the poster on phones held the first paint for 1–2 s. Keep the video download deferred until after load and first paint.
- Sketch draw-in CSS matches strokes by ink class (`.s-t` etc.), not `[pathLength]`: Chrome lowercases that selector and misses restyles when `.on` lands on the `<svg>` itself.
- Respect `prefers-reduced-motion` (engine and CSS already branch on it) and gate hover effects behind `@media (hover: hover) and (pointer: fine)`.
- The contact form has no server: it validates, then opens `mailto:` or `wa.me` with the brief. Don't add a backend unless asked.
- Images are WebP with explicit `width`/`height`; below-the-fold images use `loading="lazy"`.
